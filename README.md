# sprite-anatomy

An agent skill for building voxel models you can **cut open** — volume-first anatomy stacking with labeled interiors, rendered as crisp pixel art.

**Live demo:** https://syotturu.github.io/salmon.html — a salmon, a ro-ro ship, a jet turbine, and a butterfly-tail goldfish you can slice with a swipe.

![Made with sprite-anatomy](https://img.shields.io/badge/license-MIT-111111?style=flat-square)

## How this differs from sprite stacking

Classic sprite stacking (and the four-view carving skill in [danielwh2/sprite-stacking](https://github.com/danielwh2/sprite-stacking)) builds a fake-3D sprite by intersecting four flat views. That is great for spinning game sprites, but the carve can only ever produce a solid silhouette: **holes, overhangs, and interiors fill in solid**. There is nothing inside to find.

sprite-anatomy takes the opposite route:

| | Four-view carving | sprite-anatomy |
| --- | --- | --- |
| Model source | 4 flat views, intersected | The 3D voxel volume is defined directly, in code |
| Interiors | Impossible — everything fills solid | First-class: organs and inner structures are labeled voxels |
| Interaction | Spin / turntable | Cut anywhere — slices compose, pieces slide apart, cross-sections show the insides |
| Good for | Game sprites, props | Anatomy toys, "what's inside" demos, education, cutaway art |

Because the volume comes first, every cut is exact — like a CT scan. A salmon can be cross-cut into rounds (*wagiri*) or filleted (*sanmai-oroshi*), and the guts are where guts should be.

## How it works

1. **Volume first.** The model is a voxel grid generated by a small program (ellipsoids, superellipsoids, extrusions, hand-placed features). Each voxel carries a part label (skin, flesh, kidney, roe, window, deck…) and a base color.
2. **Baked normals, fixed sun.** Per-voxel normals are estimated from occupancy at build time. Lighting is Lambert with a sun that never moves, so faces stay readable while the model rotates.
3. **Art-resolution frame buffer.** Color / shade / depth are rendered into a low-res buffer (e.g. 250×156) and upscaled with `image-rendering: pixelated`. Outlines are drawn once, on the finished frame, from depth discontinuities — never per slice.
4. **Cutting.** A swipe defines a plane in screen space; voxels are split by the plane, pieces slide apart, and newly exposed faces get correct normals and interior colors.

## Install

Copy `skills/sprite-anatomy` into your agent's skills folder:

| Agent | Folder |
| --- | --- |
| Claude Code | `~/.claude/skills/` |
| Codex, Cursor, OpenCode, Gemini CLI, Pi | `~/.agents/skills/` |

Then ask your agent: *"Build me a cuttable voxel salmon with organs, using the sprite-anatomy skill."*

## Demo

`demo/salmon.html` is a standalone page (no dependencies) with four detailed models. Open it in any browser, drag to rotate, swipe across a model to cut it.

## Prior art

Sprite stacking is a long-standing indie game technique. This project stands on:

- Kimo ([@asynkimo](https://x.com/asynkimo/status/2121716250820964431)) — the sprite-stacking post that started it
- [SpriteCook](https://www.spritecook.ai/blog/sprite-stacking-pixel-art) — four-view carving, explained with code
- Moon stack by [@rehan](https://patch.gg/rehan/moon-stack) — the low-res frame buffer + baked-normal rendering this renderer follows
- [danielwh2/sprite-stacking](https://github.com/danielwh2/sprite-stacking) — the four-view method as an agent skill

What this skill adds is the volume-first modeling workflow and the cutting/interior model. The technique is not invented here; the stance is: **define the inside, not just the silhouette.**
